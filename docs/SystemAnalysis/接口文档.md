# 完整的校园约伴系统接口文档（枚举优化版）

## 文档说明
- **基础URL**：`http://localhost:8080/api/v1`（开发环境）
- **生产环境**：`https://api.mi.com/api/v1`
- **数据格式**：JSON
- **认证方式**：
  - 设计上采用 JWT Token（在请求头中携带 `Authorization: Bearer {token}`）
  - **当前实现（开发阶段）**：业务接口通过请求头 `X-User-Id` 识别当前登录用户，值为后端用户表中的 `id`
  - 所有「需要登录」的接口均要求携带合法的 `X-User-Id`，否则返回错误码 `1001`
- **版本**：v1

## 通用响应格式

### 成功响应
```json
{
  "code": 200,
  "message": "成功",
  "data": {},
  "timestamp": 1640995200000
}
```

### 错误响应
```json
{
  "code": 400,
  "message": "错误描述",
  "data": null,
  "timestamp": 1640995200000
}
```

## HTTP状态码说明
| 状态码 | 说明         |
| ------ | ------------ |
| 200    | 成功         |
| 400    | 请求参数错误 |
| 401    | 未授权       |
| 403    | 无权限       |
| 404    | 资源不存在   |
| 500    | 服务器内部错误 |

## 1. 用户认证模块（AUTH）

### 1.1 用户登录
- **接口说明**：用户使用学号/邮箱和密码登录
- **请求路径**：`POST /auth/login`
- **请求参数**：

| 参数名       | 类型   | 必填 | 说明         |
| ------------ | ------ | ---- | ------------ |
| identifier   | string | 是   | 学号或邮箱   |
| password     | string | 是   | 密码         |

- **请求示例**：
```json
{
  "identifier": "1120231148",
  "password": "123456"
}
```

- **响应示例**：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userInfo": {
      "id": 1,
      "email": "test@example.com",
      "nickname": "张三",
      "avatarUrl": "http://example.com/avatar.jpg",
      "userType": 0
    }
  },
  "timestamp": 1640995200000
}
```

### 1.2 用户注册
- **接口说明**：新用户注册
- **请求路径**：`POST /auth/register`
- **后台设置联动**：当 `allowPublicRegistration=false` 时，注册验证码发送和注册提交都会被拒绝。
- **请求参数**：

| 参数名   | 类型   | 必填 | 说明   |
| -------- | ------ | ---- |------|
| email    | string | 是   | 邮箱   |
| password | string | 是   | 密码   |
| verifycode| int | 是 | 验证码  |
| nickname | string | 是   | 昵称   |
| studentId| string | 否   | 学号   |

- **请求示例**：
```json
{
  "email": "test@example.com",
  "password": "123456",
  "verifycode": 123456,
  "nickname": "张三",
  "studentId": "1120231148"
}
```

- **响应示例**：
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "userId": 1
  },
  "timestamp": 1640995200000
}
```

### 1.3 刷新Token
- **接口说明**：使用refreshToken刷新访问令牌
- **请求路径**：`POST /auth/refresh`
- **请求参数**：

| 参数名       | 类型   | 必填 | 说明         |
| ------------ | ------ | ---- | ------------ |
| refreshToken | string | 是   | 刷新令牌     |

- **响应示例**：
```json
{
  "code": 200,
  "message": "刷新成功",
  "data": {
    "token": "新的访问令牌"
  },
  "timestamp": 1640995200000
}
```

### 1.4 退出登录
- **接口说明**：用户退出登录，并将当前用户在线状态标记为 OFFLINE
- **请求路径**：`POST /auth/logout`
- **请求头**：
  - `Authorization: Bearer {token}`（设计上的 JWT 方案）
  - `X-User-Id: {userId}`（当前实现使用的用户标识，必须为后端用户表中的 ID）
- **说明**：
  - 后端根据 `X-User-Id` 找到对应用户，将其 `userStatus` 更新为 `OFFLINE`
- **响应示例**：
```json
{
  "code": 200,
  "message": "退出成功",
  "data": null,
  "timestamp": 1640995200000
}
```

### 1.5 忘记密码 - 验证邮箱
- **接口说明**：用户在登录页点击“忘记密码”后，首先验证输入邮箱是否已注册且可用于找回密码。
- **请求路径**：`POST /auth/forgot/verify-email`
- **请求参数**：

| 参数名 | 类型   | 必填 | 说明           |
| ------ | ------ | ---- | -------------- |
| email  | string | 是   | 注册时使用的邮箱 |

- **请求示例**：
```json
{
  "email": "test@example.com"
}
```

- **响应示例（成功）**：
```json
{
  "code": 200,
  "message": "邮箱可用于找回密码",
  "data": {
    "emailMasked": "te***@example.com"
  },
  "timestamp": 1640995200000
}
```

- **可能的业务错误码**：
| 业务码 | 说明             |
| ------ | ---------------- |
| 1002   | 邮箱格式不合法   |
| 1003   | 邮箱未注册，无法找回密码 |

### 1.6 忘记密码 - 发送验证码
- **接口说明**：在邮箱验证通过后，向该邮箱发送用于找回密码的 6 位数字验证码。
- **请求路径**：`POST /auth/forgot/send-code`
- **请求参数**：

| 参数名 | 类型   | 必填 | 说明           |
| ------ | ------ | ---- | -------------- |
| email  | string | 是   | 已通过验证的邮箱 |

- **请求示例**：
```json
{
  "email": "test@example.com"
}
```

- **响应示例（成功）**：
```json
{
  "code": 200,
  "message": "验证码已发送",
  "data": null,
  "timestamp": 1640995200000
}
```

- **可能的业务错误码**：
| 业务码 | 说明                   |
| ------ | ---------------------- |
| 1003   | 邮箱未注册             |
| 1018   | 验证码发送频率过高（可复用 VERIFY_CODE_ERROR 描述） |

---

### 1.7 忘记密码 - 校验验证码
- **接口说明**：用户输入邮箱收到的验证码，后端校验验证码是否正确且未过期；该步骤只校验不消费验证码，最终重置密码成功后才标记为已使用。
- **请求路径**：`POST /auth/forgot/verify-code`
- **请求参数**：

| 参数名     | 类型   | 必填 | 说明           |
| ---------- | ------ | ---- | -------------- |
| email      | string | 是   | 注册邮箱       |
| verifyCode | int    | 是   | 6 位数字验证码 |

- **请求示例**：
```json
{
  "email": "test@example.com",
  "verifyCode": 123456
}
```

- **响应示例（成功）**：
```json
{
  "code": 200,
  "message": "验证码验证通过",
  "data": null,
  "timestamp": 1640995200000
}
```

- **可能的业务错误码**：
| 业务码 | 说明           |
| ------ | -------------- |
| 1018   | 验证码错误     |
| 1020   | 验证码已过期   |

---

### 1.8 忘记密码 - 重置密码
- **接口说明**：在验证码验证通过后，用户提交新密码完成重置。为安全起见，需同时携带邮箱和验证码，由后端再次校验；校验通过并保存新密码后，该验证码会标记为已使用。
- **请求路径**：`POST /auth/forgot/reset-password`
- **请求参数**：

| 参数名      | 类型   | 必填 | 说明             |
| ----------- | ------ | ---- | ---------------- |
| email       | string | 是   | 注册邮箱         |
| verifyCode  | int    | 是   | 已通过验证的验证码 |
| newPassword | string | 是   | 新密码（6-20 位） |

- **请求示例**：
```json
{
  "email": "test@example.com",
  "verifyCode": 123456,
  "newPassword": "newPassword123"
}
```

- **响应示例（成功）**：
```json
{
  "code": 200,
  "message": "密码重置成功",
  "data": null,
  "timestamp": 1640995200000
}
```

- **可能的业务错误码**：
| 业务码 | 说明             |
| ------ | ---------------- |
| 1003   | 邮箱未注册       |
| 1018   | 验证码错误       |
| 1020   | 验证码已过期     |
| 1021   | 新密码不符合规则（长度过短等） |

## 5. 管理员功能模块（ADMIN）

> 后台管理接口统一受后端 `AdminAuthInterceptor` 保护。所有 `/api/v1/admin/**` 接口都必须携带管理员用户的 `X-User-Id` 请求头；未登录或用户不存在返回 HTTP 401，普通用户或封禁用户返回 HTTP 403。`Authorization: Bearer {token}` 可按前端现有登录态继续携带，但当前开发阶段的后端管理员身份以 `X-User-Id` 对应用户的 `userType=ADMIN` 为准。
> 后台管理列表接口的分页参数会统一规整：`page < 1` 时按 `1` 处理，`size < 1` 时按 `1` 处理，`size > 100` 时按 `100` 处理。

## 7.5 AI 助手模块（AGENT）

### 7.5.1 AI 会话与消息接口

> 权限说明：以下接口均需要携带 `X-User-Id` 请求头。当前实现由 Java 后端维护会话、消息和记忆，并代理到 Python Agent 服务。

| 功能 | 方法与路径 | 说明 |
| --- | --- | --- |
| 创建会话 | `POST /agent/conversations` | 创建一个新的 AI 会话 |
| 会话列表 | `GET /agent/conversations` | 获取当前用户的 AI 会话列表 |
| 消息列表 | `GET /agent/conversations/{cid}/messages` | 获取指定会话的历史消息 |
| 删除会话 | `DELETE /agent/conversations/{cid}` | 删除指定 AI 会话及消息 |
| 非流式发送 | `POST /agent/conversations/{cid}/messages` | 发送用户消息并等待完整 AI 回复 |
| 流式发送 | `POST /agent/conversations/{cid}/messages/stream` | 通过 SSE 接收 Agent 执行状态与回复文本 |
| 记忆列表 | `GET /agent/memory` | 获取当前用户的 AI 长期记忆 |
| 删除记忆 | `DELETE /agent/memory/{memId}` | 删除指定 AI 记忆 |

### 7.5.2 流式消息请求

**请求路径**：`POST /agent/conversations/{cid}/messages/stream`

**请求头**：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| X-User-Id | long | 是 | 当前登录用户 ID |
| Content-Type | string | 是 | `application/json` |
| Accept | string | 建议 | `text/event-stream` |

**请求体**：

```json
{
  "message": "帮我查一下良乡校区附近适合打篮球的地方"
}
```

### 7.5.3 SSE 事件协议

| 事件名 | data 格式 | 说明 |
| --- | --- | --- |
| `agent_step` | JSON | Agent 当前执行阶段，例如意图分析、规划、订单智能体处理、地图智能体处理 |
| `intent` | JSON | 小模型意图分析结果，不使用简单字符匹配分类 |
| `status` | 文本或 JSON | 兼容旧版状态提示 |
| `tool_start` | JSON | 预留：工具开始调用 |
| `tool_result` | JSON | 预留：工具返回结果 |
| `artifact` | JSON | 预留：订单卡片、动态卡片、地图视图等结构化展示数据 |
| `confirm_required` | JSON | 预留：写操作执行前的确认草稿 |
| `delta` | 文本 | AI 回复正文分块 |
| `done` | 空字符串 | 流式响应结束 |
| `error` | 文本 | Agent 或 SSE 处理失败 |

`agent_step` 示例：

```json
{
  "phase": "intent",
  "agent": "router",
  "title": "分析用户意图",
  "detail": "正在用轻量模型判断任务类型、风险和需要的子智能体",
  "state": "running"
}
```

`intent` 示例：

```json
{
  "primary_intent": "order.search",
  "domain": "order",
  "operation_type": "read",
  "requires_confirmation": false,
  "confidence": 0.86,
  "summary": "用户想查询可参与的篮球约伴活动",
  "missing_slots": [],
  "suggested_agents": ["order_query"],
  "next_action": "execute_read_tools"
}
```

前端应优先使用结构化事件渲染执行状态、确认卡片和结果卡片；`delta` 仅用于最终自然语言回复。

### 7.5.4 写操作确认卡片

`confirm_required` 示例：

```json
{
  "type": "confirmation",
  "title": "确认发布篮球约伴活动",
  "description": "将创建一个良乡校区篮球约伴活动",
  "actionKind": "order.create",
  "fields": [
    { "label": "活动类型", "value": "篮球" },
    { "label": "校区", "value": "良乡校区" },
    { "label": "地点", "value": "良乡大学城公园文苑篮球场" },
    { "label": "时间", "value": "明天下午 3 点" },
    { "label": "人数", "value": "8 人" }
  ],
  "missingFields": [],
  "requiresConfirmation": true,
  "confirmMessage": "我确认执行这个草稿：确认发布篮球约伴活动",
  "editMessage": "我想修改这个草稿：确认发布篮球约伴活动",
  "cancelMessage": "取消这个草稿：确认发布篮球约伴活动",
  "reply": "我已经整理好操作草稿。确认无误后，请点击确认执行或直接回复“确认”。"
}
```

前端收到 `confirm_required` 后应渲染为确认卡片，而不是普通文本。用户点击“确认执行”时发送 `confirmMessage`；点击“修改草稿”时发送 `editMessage`；点击“取消”时发送 `cancelMessage`。在收到确认前，Agent 不应调用任何会修改数据库的工具。

### 8.2 后端接口实现示例（Spring Boot）

```java
// OrderController.java
@RestController
@RequestMapping("/api/v1/orders")
@RequiredArgsConstructor
@Slf4j
public class OrderController {
    
    private final OrderService orderService;
    
    @PostMapping
    public ApiResponse<Long> createOrder(
            @Valid @RequestBody CreateOrderRequest request,
            @AuthenticationPrincipal UserDetails user) {
        Long userId = Long.parseLong(user.getUsername());
        Long orderId = orderService.createOrder(request, userId);
        return ApiResponse.success(orderId);
    }
    
    @GetMapping
    public ApiResponse<PageResult<OrderVO>> getOrders(
            @RequestParam(defaultValue = "1") Integer page,
            @RequestParam(defaultValue = "10") Integer size,
            @RequestParam(required = false) OrderStatus status,
            @RequestParam(required = false) ActivityType activityType) {
        
        OrderQuery query = OrderQuery.builder()
            .page(page)
            .size(size)
            .status(status)
            .activityType(activityType)
            .build();
            
        PageResult<OrderVO> result = orderService.getOrders(query);
        return ApiResponse.success(result);
    }
    
    @GetMapping("/{orderId}")
    public ApiResponse<OrderDetailVO> getOrderDetail(@PathVariable Long orderId) {
        OrderDetailVO detail = orderService.getOrderDetail(orderId);
        return ApiResponse.success(detail);
    }
}

// ApiResponse.java - 统一响应格式
@Data
@AllArgsConstructor
@NoArgsConstructor
public class ApiResponse<T> {
    private Integer code;
    private String message;
    private T data;
    private Long timestamp;
    
    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(200, "成功", data, System.currentTimeMillis());
    }
    
    public static <T> ApiResponse<T> success(String message, T data) {
        return new ApiResponse<>(200, message, data, System.currentTimeMillis());
    }
    
    public static ApiResponse<?> error(Integer code, String message) {
        return new ApiResponse<>(code, message, null, System.currentTimeMillis());
    }
}

// 枚举定义示例
public enum ActivityType {
    BASKETBALL(0, "篮球"),
    BADMINTON(1, "羽毛球"),
    MEAL(2, "吃饭"),
    STUDY(3, "自习"),
    MOVIE(4, "看电影"),
    RUNNING(5, "跑步"),
    GAME(6, "游戏"),
    OTHER(7, "其他活动");
    
    private final int code;
    private final String desc;
    
    ActivityType(int code, String desc) {
        this.code = code;
        this.desc = desc;
    }
    
    public int getCode() { return code; }
    public String getDesc() { return desc; }
    
    public static ActivityType fromCode(int code) {
        for (ActivityType type : values()) {
            if (type.code == code) return type;
        }
        return OTHER;
    }
```

## 10. 注意事项

### 10.1 安全性考虑
1. **密码安全**：密码必须加密存储，使用BCrypt或Argon2算法
2. **SQL注入防护**：使用参数化查询或ORM框架
3. **XSS防护**：对用户输入进行转义处理
4. **CSRF防护**：使用CSRF Token或SameSite Cookie
5. **文件上传**：限制文件类型和大小，重命名上传文件

### 10.2 性能优化
1. **分页查询**：所有列表接口必须支持分页
2. **数据库索引**：为常用查询字段建立索引
3. **缓存策略**：频繁查询的数据使用Redis缓存
4. **CDN加速**：图片和视频文件使用CDN分发
5. **连接池**：数据库和Redis使用连接池

### 10.3 可扩展性
1. **微服务拆分**：用户、订单、动态可拆分为独立服务
2. **消息队列**：异步处理邮件发送、消息通知等
3. **API版本控制**：为未来API变更预留空间
4. **监控告警**：集成Prometheus和Grafana监控

### 10.4 团队协作
1. **接口文档**：使用Swagger自动生成API文档
2. **代码规范**：统一代码风格，使用ESLint/Checkstyle
3. **Git流程**：采用Git Flow或GitHub Flow工作流
4. **Code Review**：所有代码合并前需经过Code Review
5. **持续集成**：配置GitHub Actions或Jenkins流水线
